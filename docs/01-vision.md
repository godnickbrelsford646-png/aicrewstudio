# 01. Видение продукта

## Проблема
Контент‑мейкеру нужно постоянно: придумывать темы, проверять факты, писать тексты на двух языках, делать обложки, адаптировать пост под каждый канал и публиковать по расписанию. В одиночку — это рутина на 4–8 часов в день.

## Решение
**AiCrewStudio** — это «студия ИИ‑команды». Пользователь:
1. Создаёт **Проект** (нишу/блог/канал).
2. Получает готовую **команду агентов** с типовыми ролями.
3. Настраивает каждого агента: модель GPT, температура, промт, доп. параметры.
4. Привязывает каналы публикации (Telegram, VK, X, TikTok, YouTube Shorts и т.д.).
5. Включает проект — система сама гонит цикл «темы → статьи → картинки → публикация» по расписанию.

## Ключевые принципы
1. **n8n‑like пайплайн.** Каждый агент — нода. Ноды связаны, передают результат и могут читать ответы любых предыдущих.
2. **Прозрачность.** В каждого агента можно «провалиться» и посмотреть его последние действия по каждой теме (входы, промт, ответ модели, токены, цена).
3. **Стоимость под контролем.** На каждом шаге фиксируется расход токенов и денег, ведётся бюджет проекта.
4. **Идемпотентность.** Любой шаг можно перезапустить без дублирования публикаций.
5. **Память.** Хранится список уже опубликованных тем — генератор тем не повторяется.
6. **Мульти‑язычность.** Параллельно ведутся RU и EN ветки. У каждой — свой редактор и свой QA.

## Целевые пользователи
- **MVP:** сам автор (single‑user), один аккаунт без биллинга.
- **v1:** небольшие медиа‑команды/личные бренды.
- **v2:** агентства с подписками и тарифами, white‑label.

## Нефункциональные требования
- **Надёжность:** retry с backoff на каждом вызове LLM/инструмента, dead‑letter‑queue.
- **Безопасность:** все API‑ключи — в шифрованном vault (Fernet/age), не в БД в plaintext.
- **Аудит:** иммутабельный лог всех LLM‑вызовов (prompt, model, params, response, cost) минимум 90 дней.
- **Производительность:** один проект — до 50 публикаций в сутки без деградации.
- **Локализация UI:** RU + EN.

## Что выходит за рамки MVP
- Биллинг и подписки (но архитектурно заложено).
- Real‑time коллаборация (multi‑user проект).
- Мобильное приложение.
- Видео‑команда (заложена, реализуем во 2‑й итерации).
