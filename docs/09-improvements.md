# 09. Доработки и идеи (что вы не учли)

> Здесь — мои предложения по тому, что усилит проект. Можно брать частично, можно целиком, можно отложить на потом.

## 1. Память и анти‑дубликаты

- **Семантический дедуп тем.** Эмбеддинги каждой `topic.title + summary` и проверка cosine‑similarity к опубликованным за N дней. Если ≥ 0.85 — отбрасываем как дубль. Иначе генератор будет переименовывать ту же тему синонимами.
- **Family‑level дедуп.** Кластеризовать публикованные темы (HDBSCAN) и не публиковать слишком много из одного кластера подряд — ради разнообразия канала.
- **«Календарь тем».** Кроме «не повторяться», стоит уметь принудительно заказывать темы: «в понедельник — рубрика Q&A», «в пятницу — обзор недели». Параметр `editorial_calendar` на проект.

## 2. Качество и фактчек

- **Фактчек как отдельная нода**, а не только в QA. Пройтись по утверждениям статьи через web_search, пометить проблемные.
- **Доверие к источникам.** Список доменов с приоритетами (whitelist/greylist/blacklist). Researcher и Validator штрафуют источники из greylist.
- **Plagiarism guard.** Проверка финального текста на близость к существующим публикациям (через перефразирование + поиск точных n‑грамм).
- **Style guide на проект.** Поле `style_guide.md` — задаёт тон голоса, табу‑слова, обязательные блоки. Подмешивается во все писательские агенты.

## 3. Безопасность контента

- **Content moderation layer** перед публикацией: проверка на запрещённые темы, оскорбления, медицинские/юридические заявления без оговорок.
- **Регуляторика по странам.** Для RU‑контента проверять упоминания «иностранных агентов»/«экстремистских организаций» — пометить, добавить плашку или остановить публикацию.
- **Авторские права на изображения.** Если используются стоки — проверять лицензию. Если AI‑gen — добавлять метку «AI generated» (требование некоторых платформ).

## 4. Управление пайплайном

- **Visual DAG editor (как в n8n)** на React Flow. Можно перетаскивать ноды, вставлять между ними кастомные. Это будущее v1, но архитектурно ноды должны быть «плагины».
- **Версионирование промтов.** Каждое изменение `prompt_template` сохраняется как `agent_prompt_version`. У `agent_run` хранится `prompt_version_id`. Можно откатиться и сравнить качество (A/B по версии промта).
- **Сравнительные прогоны (A/B).** Запустить два варианта агента (модель A vs B, температура 0.3 vs 0.7) на одной теме и автоматически выбрать лучший по метрикам QA.
- **Human‑in‑the‑loop checkpoint.** На любом шаге можно поставить флажок «остановиться и спросить юзера». Удобно на старте — пока не доверяете полной автоматике.

## 5. Каналы и публикация

- **Multi‑variant posts.** На один канал готовить 2–3 варианта подводки и автоматически выбирать по предсказанной CTR (ML‑моделью или простыми эвристиками: длина, эмодзи, вопросительность).
- **Best‑time to post.** Со временем учиться по метрикам канала, в какие слоты охват выше — и подсказывать `slots`.
- **Cross‑posting protection.** Если статья опубликована в TG и VK, X — не дублировать тот же текст в Threads/Mastodon (или хотя бы перефразировать сильнее).
- **UTM/трекинг.** Автоматически добавлять UTM‑метки к ссылкам в постах, чтобы в аналитике видеть источник.

## 6. Видео‑команда (что я бы добавил к вашему списку)

- **Hook‑auditor** — проверяет первую секунду на «цепкость».
- **B‑roll fetcher** — альтернатива дорогой генерации видео: брать стоки с Pexels/Pixabay.
- **Loudness normalization** (`-14 LUFS`) — иначе TikTok/Reels глушат звук.
- **Caption density check** — субтитры не должны лететь быстрее ~3 слов/сек.
- **Storyboard preview** в UI с возможностью регенерить одну сцену.
- **Watermark/branding** — лого канала в углу.
- **Регенерация только voiceover** — если только перевод плохой, не пересобирать всё видео.

## 7. Аналитика и обратная связь

- **Метрики публикаций.** Тянуть likes/views/comments/CTR с каналов (где есть API) и сохранять рядом с `posts`. На дашборде — ТОП тем по охвату.
- **Reinforcement loop.** Удачные темы (по реальным метрикам) — усиливают веса в TopicRanker (онлайн‑обучение). Плохие — штрафуют.
- **«Учиться на провалах».** Если пост провалился, агент‑аналитик пишет постмортем и обновляет `style_guide` или `forbidden_patterns`.

## 8. Стоимость

- **Cost dashboard** на проект и на агента, разрезы: модель / инструмент / месяц.
- **Бюджет с мягкой и жёсткой границей.** Soft (80%) — уведомление; hard (100%) — пауза.
- **Cheap‑first роутинг.** Простые шаги (rewriter, headline) — на дешёвой модели; сложные (research_validator, qa) — на топовой.
- **Кэш веб‑поиска.** Один и тот же запрос за час — отдавать из кэша.

## 9. Надёжность и операционка

- **Idempotency keys** на публикацию (`(article_id, channel_id, scheduled_for)`), чтобы повторный запуск воркера не публиковал дубль.
- **Dead‑letter queue** + UI «зависшие задачи».
- **Health‑check каналов.** Раз в час дёргать `getMe`/`me` — если токен умер, помечать канал и слать уведомление.
- **Backups БД** — pg_dump раз в сутки в S3, retention 30 дней.

## 10. Безопасность

- **Encrypted credentials** (Fernet + master key из env/секретницы).
- **Audit log** действий пользователя (включил/выключил проект, изменил промт, выпустил публикацию).
- **2FA** для UI (TOTP) — даже в single‑user, потому что в системе живут токены каналов.
- **Изоляция инструментов.** `fetch_url` запрещает приватные подсети (SSRF‑защита).

## 11. UX

- **«Песочница» агента.** В карточке агента — кнопка «Запустить тестово» с произвольным input, без записи в боевой пайплайн.
- **Сравнение версий статьи.** Diff между «до QA» и «после QA», между «универсальной» статьёй и постом для канала.
- **Темы недели/превью.** Календарь, на котором видно, какая тема в какой канал и в какой слот пойдёт. Можно перетаскивать.

## 12. Локализация и расширяемость

- **Языки** — заложить i18n не только для UI, но и для языковых веток редакторов. Добавить третий язык — это `editor_es`, `qa_es`, добавление каналов с `language=es`. Должна быть generic фабрика, а не хардкод RU/EN.
- **Плагины публикаторов** — через registry/entry points: добавить новый канал = новый класс + миграция enum + UI‑форма для creds.

## 13. Подписки (когда дойдёт до биллинга)

- Лимиты: кол‑во проектов, прогонов в сутки, видео в месяц, токенов в месяц.
- Включение/выключение фич по тарифу (видео‑команда — только Pro/Team).
- Stripe + YooKassa параллельно (для RU‑аудитории).
- Грейс‑период 3 дня после неуспешного списания.

## 14. Тестирование и качество кода

- **Контрактные тесты для агентов** — фиксированный input + замокированный LLM ответ → ожидаемая структура output.
- **Snapshot‑тесты промтов** — рендер промта по шаблону должен совпадать с эталоном (защита от случайных изменений).
- **VCR‑кассеты для публикаторов** — записанные ответы API, чтобы тесты не били в реальные сервисы.
- **`pre-commit`:** ruff, black, mypy, eslint, prettier.
