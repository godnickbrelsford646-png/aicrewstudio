# 04. Пайплайн агентов (DAG)

## Обзор

Пайплайн делится на 3 фазы:
1. **Topic phase** — раз в сутки (или по триггеру), наполняет «банк тем».
2. **Article phase** — пишет статьи по топ‑N тем из банка, для RU и EN ветки.
3. **Publication phase** — постоянная: каждый канал по своему расписанию забирает готовую статью, переписывает и публикует.

Каждая фаза — отдельный `PipelineRun` (можно запускать независимо).

## Фаза 1. Topic phase

```
        ┌──────────────────────┐
        │ 1. TopicGenerator    │◄─── memory: published topics за N дней
        │    (web_search)      │
        └──────────┬───────────┘
                   ▼
        ┌──────────────────────┐
   ┌───►│ 2. TopicValidator    │ если valid_count < target → петля назад
   │    │    (web_search)      │
   │    └──────────┬───────────┘
   │               ▼
   │    ┌──────────────────────┐
   │    │ 3. TopicRanker       │
   │    └──────────┬───────────┘
   │               ▼
   │           topics with score → банк тем
   └──── повторить до набора N подтверждённых тем
```

### Детали
- **TopicGenerator** на каждой итерации получает: `today` (если включено), `forbidden_topics` (из памяти + уже подтверждённые в текущем прогоне).
- **TopicValidator** возвращает: `[{title, summary_extended, sources, is_valid, reason}]`. Только `is_valid=true` идут дальше.
- **Loop guard:** `max_iterations` (по умолчанию 5), чтобы не зациклиться на дорогих веб‑поисках.
- **TopicRanker** оценивает по критериям: `relevance`, `novelty`, `virality`, `evergreen`, `sources_quality`. Сумма → `score_total`. Каждый критерий — 0..10, веса в `params`.

## Фаза 2. Article phase

Запускается для каждой темы из топ‑N (где N = `daily_articles_target`). Параллельно для RU и EN.

```
Topic
  │
  ▼
┌────────────────────┐
│ 4. Researcher      │  (web_search, fetch_url)
└────────┬───────────┘
         ▼
┌────────────────────┐
│ 5. ResearchValidator│ (web_search) — переписывает, исправляя ошибки
└────────┬───────────┘
         ▼
┌────────────────────┐
│ 6. ArticleWriter   │ — большая «универсальная» статья
└────────┬───────────┘
         ├──────────────┬───────────────┐
         ▼              ▼               ▼
   ┌──────────┐   ┌──────────────┐  ┌────────────┐
   │ Headlines│   │ ImagePrompt  │  │ (другое:   │
   │  writer  │   │   + ImageGen │  │  TL;DR,    │
   └────┬─────┘   └──────┬───────┘  │  тэги ...) │
        │                │          └─────┬──────┘
        └────────┬───────┴────────────────┘
                 ▼
           ┌────────────┐
           │ 9. QA      │ — выбирает headline + image, правит мелочи
           └─────┬──────┘
                 ▼
           Article (status=qa_passed)
```

### Детали
- **Researcher** возвращает структурированное досье: `{facts:[], stats:[], quotes:[], sources:[]}`.
- **ResearchValidator** проходит по фактам, делает веб‑проверку и **возвращает исправленную версию** (а не лог ошибок).
- **ArticleWriter** пишет одну «большую» статью (~6–10к знаков) — это base‑версия, под каналы будет урезаться.
- **HeadlineWriter** возвращает массив заголовков (`headlines_per_article`).
- **ImagePromptWriter + ImageGen** генерит `images_per_article` картинок. Если `images_per_article=1` → QA её и берёт без выбора.
- **QA** — может быть разделён на два саб‑агента для контроля сложности:
  - `QA.Editorial` — проверяет текст: фактчек, тон, грамматика, выбор заголовка.
  - `QA.Visual` — выбирает лучшую картинку.
  - Финальный шаг — `QA.Compose` — собирает итог: `chosen_headline`, `chosen_image_id`, итоговый `body_full`.

Дублируется на **двух языковых ветках** (RU, EN) с независимыми редакторами и QA.

## Фаза 3. Publication phase

```
Article (qa_passed, lang)
       │
       ▼
  по каждому Channel с этим lang:
       │
       ▼
┌──────────────────────┐
│ ChannelRewriter      │ — переписывает body под канал (лимит знаков, стиль)
│  (свой промт у канала)│
└─────────┬────────────┘
          ▼
   Post (scheduled_for = ближайший слот)
          ▼
   ┌──────────────────┐
   │ Publisher (cron) │ — в нужный момент публикует через API канала
   └──────────────────┘
          ▼
   Publication (external_url, published_at)
```

### Стратегия выбора темы для канала
- `by_rank` — сортируем `articles` по `topic.score_total` среди ещё не опубликованных в этот канал.
- `random_among_written` — берём случайную статью среди тех, что уже написаны (`status=qa_passed`), исключая опубликованные ранее в этот канал.
- Гарантия: канал никогда не возьмёт «несуществующую» тему — только из пула написанных.

### Видео‑каналы
- У видео‑каналов **нет ChannelRewriter**.
- Берётся готовый `MediaAsset(kind=video)` нужного языка (см. `07-video-team.md`), публикуется в слот.

## Идемпотентность и повтор
- Любой шаг можно перезапустить: `agent_runs` создаются заново, но `topics`/`articles`/`posts` — апдейтятся (не дублируются).
- `posts` имеет уникальный ключ `(article_id, channel_id)` — повторная публикация в тот же канал требует явного флага «republish».

## Передача контекста
- AgentExecutor рендерит промт по шаблону. Доступные переменные:
  - `{{ project }}`, `{{ today }}`, `{{ language }}`.
  - `{{ inputs }}` — JSON всех предыдущих нод текущего прогона (по ролям).
  - `{{ memory.published_topics }}` — для TopicGenerator.
  - Любая нода может явно `read` любую предыдущую — это объявляется в `agent.params.depends_on`.
